**EDA**

Скрипт выполняет exploratory data analysis для одного или нескольких YOLO-датасетов. Он принимает на вход YAML-файл датасета в формате YOLO, анализирует только test split. Далее формируется статистика и сохраняется результат в JSON для дальнейшей визуализации в GUI.

**Подробное описание**

Скрипт:

- принимает на вход YAML-файл датасета в формате YOLO;
- анализирует только test split (секция test в YAML);
- для каждого указанного в test пути находит изображения и соответствующие label-файлы;
- проверяет разметку в формате YOLO (валидация координат, проверка диапазонов);
- считает статистику по изображениям, объектам, классам и размерам объектов;
- при наличии файла shooting_conditions.json подтягивает metadata по условиям съёмки (поддерживаются два уровня аннотаций: sequence и image);
- формирует отчёт в формате JSON;
- вся визуализация графиков выполняется на стороне GUI на основе данных из JSON.

**Что подаётся на вход**

Скрипт принимает YAML-файл датасета в стандартном формате YOLO.


Пример:

```yaml
train:
  - /path/to/train/visible/images

val:
  - /path/to/val/visible/images

test:
  - /path/to/test/scene_1/visible/images
  - /path/to/test/scene_2/visible/images
  - /path/to/test/scene_3/visible/images

nc: 1
names:
  0: drone
```

Важно: скрипт анализирует только секцию test. Секции train и val игнорируются. Если в test указано несколько путей, все они будут проанализированы и объединены в одну статистику.

Что требуется от структуры датасета

Скрипт рассчитан на типичную YOLO-структуру, где рядом с изображениями существуют соответствующие label-файлы.

Ожидаемая структура:

test/
├── scene_001/
│   └── visible/
│       ├── images/
│       │   ├── frame_0001.jpg
│       │   ├── frame_0002.jpg
│       │   └── ...
│       └── labels/
│           ├── frame_0001.txt
│           ├── frame_0002.txt
│           └── ...
├── scene_002/
│   └── visible/
│       ├── images/
│       └── labels/
└── shooting_conditions.json   (опционально)

Требования:

- изображения лежат в директории .../images

- label-файлы лежат в соответствующей директории .../labels

- label-файлы имеют те же имена, что и изображения, с расширением .txt

- содержимое label-файлов соответствует формату YOLO: class_id x_center y_center width height (нормализованные координаты)

**Поддержка metadata по условиям съёмки**

Если рядом с анализируемыми директориями найден файл shooting_conditions.json, скрипт включает эту информацию в анализ.

Ожидаемое имя файла:

shooting_conditions.json

Поддерживаются два режима разметки условий съёмки.

Разметка по последовательностям:
```
{
  "annotation_level": "sequence",
  "sequences": {
    "scene_001": ["day"],
    "scene_002": ["night", "blur"],
    "scene_003": ["fog", "low_visibility"]
  }
}
```
Разметка по изображениям:
```
{
  "annotation_level": "image",
  "images": {
    "frame_0001.jpg": ["day"],
    "subdir/frame_0002.jpg": ["night"]
  }
}
```

Если metadata отсутствует, анализ всё равно выполняется, просто блок статистики по условиям съёмки будет пустым.

**Какие статистики считаются**

Скрипт считает:

• общее число изображений;
• общее число объектов;
• число битых строк в label-файлах;
• число отсутствующих label-файлов;
• число пустых label-файлов;
• число label-файлов только с битыми строками;
• число фоновых изображений (отсутствующие + пустые label-файлы);
• распределение числа объектов на изображение;
• распределение классов;
• распределение размеров объектов (small / medium / large по порогам COCO);
• распределение разрешений изображений;
• число каналов изображений;
• статистику по условиям съёмки (по изображениям и по последовательностям), если присутствует metadata.

Размеры объектов делятся по порогам COCO:

	•	small: площадь < 32^2;
	•	medium: 32^2 <= area < 96^2;
	•	large: площадь >= 96^2.

**Что создаётся на выходе**

Для каждого обработанного YAML-файла создаётся директория:

<output_root>/<dataset_name>/
Где dataset_name берётся из поля name в YAML или из имени файла, если поле отсутствует.

Внутри директории создаётся:

stats.json — основной результат работы скрипта, содержит всю собранную статистику и данные для построения графиков

Пример структуры stats.json:

'''
{
  "dataset_name": "full_cfg",
  "images_total": 35482,
  "objects_total": 35482,
  "missing_label_files": 0,
  "empty_label_files": 0,

'''

**Основной результат**

Главный результат работы скрипта — JSON-отчёт stats.json. Именно он предназначен для дальнейшего чтения бэкендом или промежуточной прослойкой перед веб-интерфейсом. Файл содержит как агрегированную статистику, так и данные для построения графиков (plot_data).


**Запуск**

Примеры запуска:
### Запуск с указанием YAML-файла
python eda.py --yaml /path/to/dataset.yaml

### Запуск с указанием выходной директории
python eda.py --yaml /path/to/dataset.yaml --output-root /custom/output

### Запуск с использованием YAML по умолчанию (из INPUT_YAMLS)
python eda.py
