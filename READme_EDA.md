**EDA**

Скрипт выполняет exploratory data analysis для одного или нескольких YOLO-датасетов. Он принимает общий YAML запуска, в котором перечислены датасеты и выбранные для них сплиты. Для каждого датасета скрипт считывает его dataset YAML, анализирует указанные изображения и label-файлы, формирует статистику по каждому датасету отдельно, а также строит общий объединённый анализ по всем выбранным датасетам.

**Подробное описание**

Скрипт:

- считывает входной Run YAML;
- определяет, какие датасеты и какие сплиты нужно анализировать;
- для каждого датасета открывает соответствующий dataset YAML;
- находит изображения и соответствующие label-файлы;
- проверяет разметку в формате YOLO;
- считает статистику по изображениям, объектам, классам и размерам объектов;
- при наличии файла `shooting_conditions.json` подтягивает metadata по условиям съёмки;
- формирует отдельные отчёты для каждого датасета;
- формирует общий объединённый отчёт по всем выбранным датасетам;
- может сохранять результаты в JSON, Markdown и PNG.

**Что подаётся на вход**

Скрипт принимает один или несколько Run YAML-файлов.

Пример:

```yaml
datasets:
  - yaml_path: /path/to/dataset_a.yaml
    selected_splits: [test]

  - yaml_path: /path/to/dataset_b.yaml
    selected_splits: [train, val]
```

Здесь:

	•	yaml_path — путь к YAML конкретного датасета;
	•	selected_splits — список сплитов, которые нужно анализировать;
	•	допустимые значения сплитов: train, val, test;

Что требуется от структуры датасета

Скрипт рассчитан на типичную YOLO-структуру, где рядом с изображениями существуют соответствующие label-файлы.

Поддерживаются основные варианты организации данных:

	•	путь сразу указывает на images;
	•	путь указывает на split-директорию, внутри которой есть images и labels;
	•	путь указывает на директорию, где изображения и labels расположены по стандартной YOLO-логике;
	•	для каждого изображения должен существовать соответствующий .txt label-файл с тем же относительным путём.

**Поддержка metadata по условиям съёмки**

Если рядом со сплитом или датасетом найден файл shooting_conditions.json, скрипт включает эту информацию в анализ.

Ожидаемое имя файла:

shooting_conditions.json

Поддерживаются два режима разметки условий съёмки.

Разметка по последовательностям:
```
{
  "dataset_name": "example_dataset",
  "split": "test",
  "annotation_level": "sequence",
  "condition_labels": ["day", "night", "blur", "overexposed", "low_visibility"],
  "sequences": {
    "scene_001": ["day"],
    "scene_002": ["night", "blur"]
  }
}
```
Разметка по изображениям:
```
{
  "dataset_name": "example_dataset",
  "split": "test",
  "annotation_level": "image",
  "condition_labels": ["day", "night", "blur", "overexposed", "low_visibility"],
  "images": {
    "img_0001.jpg": ["day"],
    "subdir/img_0002.jpg": ["night"]
  }
}
```

Если metadata отсутствует, анализ всё равно выполняется, просто блок статистики по условиям съёмки будет пустым.

**Какие статистики считаются**

Скрипт считает:

	•	общее число изображений;
	•	общее число объектов;
	•	число битых строк в label-файлах;
	•	число отсутствующих label-файлов;
	•	число background-изображений;
	•	распределение числа объектов на изображение;
	•	распределение классов;
	•	распределение размеров объектов;
	•	распределение разрешений изображений;
	•	число каналов изображений;
	•	сводки по YAML-сплитам и фактическим split-именам в путях;
	•	статистику по условиям съёмки, если присутствует metadata.

Размеры объектов делятся по порогам COCO:

	•	small: площадь < 32^2;
	•	medium: 32^2 <= area < 96^2;
	•	large: площадь >= 96^2.

**Что создаётся на выходе**

Для каждого запуска создаётся отдельная директория сессии вида:

EDA_session_<timestamp>

Внутри неё создаются:

	•	отчёты по каждому датасету;
	•	объединённый глобальный отчёт GLOBAL_MERGED;
	•	metadata текущей сессии.

Для каждого датасета создаются:

	•	report.json — общая статистика по датасету;
	•	train.json, val.json, test.json — статистика по отдельным сплитам, если они анализировались;
	•	report.md — читаемый markdown-отчёт;
	•	PNG-графики, если генерация графиков включена.

Для глобального объединённого анализа создаются:

в директории GLOBAL_MERGED:

	•	report.json — общая статистика по всем выбранным датасетам;
	•	train.json, val.json, test.json — глобальная статистика по сплитам;
	•	report.md — markdown-отчёт;
	•	PNG-графики, если генерация графиков включена.

Дополнительно создаётся:

	•	session_meta.json — служебная информация о запуске:
	•	какие Run YAML-файлы были поданы на вход;
	•	какие dataset YAML использовались;
	•	какие сплиты были выбраны;
	•	какой режим определения split использовался;
	•	какие параметры анализа были заданы.

**Основной результат**

Главный результат работы скрипта — JSON-отчёты.

Именно они предназначены для дальнейшего чтения бэкендом или промежуточной прослойкой перед веб-интерфейсом. Markdown и PNG являются дополнительными артефактами для ручной проверки и визуального анализа.

**Основные выходные артефакты**

На практике ключевыми выходами являются:

	•	report.json для каждого датасета;
	•	train.json, val.json, test.json для каждого датасета;
	•	GLOBAL_MERGED/report.json;
	•	GLOBAL_MERGED/train.json, GLOBAL_MERGED/val.json, GLOBAL_MERGED/test.json;
	•	session_meta.json.

**Запуск**

Примеры запуска:

python eda.py --yaml /path/to/run.yaml

python eda.py --yamls /path/to/run1.yaml /path/to/run2.yaml

Дополнительно можно указать:

--output-root /path/to/output
--use-path-split-inference
--no-json
--no-markdown
--no-plots
